# v1.14 scope — F21 finalize-window study (assurance cycle)

**Status:** draft for the maintainer's must-pin review. Written 2026-09-23
against `main` at `3ecac3d` (F21 finalize preflight, #199). Mirrors
`docs/v1.13-scope.md` (why-now → structural facts → forks Q14.x with a
recommendation each → assurance → risks → out of scope → sequence).

One item, **no crate change**: execute the pre-committed measurement protocol
for the `Sm4CbcDecryptor::finalize()` timing window on one pinned host, record
exactly one of three labels, and close or re-scope F21 by that label. No
version bump, no publish, no CI gate — the v0.14 / v1.10 assurance-cycle
precedent. The two deliberately leaky control builds never enter this tree.

---

## 1. Why now

F21 has been open since v1.10. Q10.9 measured the composite
`mode_cbc::decrypt` window and found it **blind**: the constant-time build read
`|tau|` 0.0129 and the early-return leaky control 0.0185 (indistinguishable),
while the 10 000× amplified control read 11.6 — the measurement path works, the
window is ~10⁴× too coarse, because the key schedule and both block decrypts
(~10⁵ masked S-box operations) dwarf a ~15-comparison strip. Q10.9 named the
follow-up: time `finalize()` alone, with the key schedule and block decrypts in
the untimed prologue, and named the blocker: `CtRunner::run_one` takes `Fn`,
`finalize(self)` consumes the decryptor.

Since then the pieces have been built but never run together:

- **Upstream:** `docs/f21-finalize-preflight.md` + `tests/f21_finalize_inputs.rs`
  (#199) fix the two invalid-padding classes and prove the single-consumption
  wrapper (`RefCell<Option<Sm4CbcDecryptor>>`, take once, panic on reuse).
- **Research clone only (not on `origin`):** a three-target narrow-window bench
  (T1), the two leaky control patches (T2), and a pre-measurement protocol
  (T3) that fixes machine, toolchain, harness, build identities, sample count,
  rounds, order, observables, criteria, labels and budget *before* any number
  exists. Identities are pinned in §2.

Nothing else is owed (1.13.0 live, nightly fuzz and dudect green). The study
either yields a label or records a negative; either way F21 stops being an
open-ended backlog line. That is the whole cycle.

## 2. Structural facts (verified against code and host, 2026-09-23)

**Harness.** `dudect-bencher` 0.7.0, `Cargo.lock` checksum
`6a6174adfb35811a6845001876823965032406784c36e795edb84a74353455e1`.
`CtRunner::run_one<T, F: Fn() -> T>` (`ctbench.rs:341–347`) reads
`Instant::now()`, evaluates `black_box(f())` **once**, reads `Instant::now()`
again, pushes the difference under the sample's class. The returned `T` is a
temporary dropped at the end of the `black_box` statement — **before** the
second clock read. So the timed window is: closure body + drop of its return
value + `black_box` + the two clock reads.

**Target.** `Sm4CbcDecryptor::finalize(mut self) -> Option<Vec<u8>>`
(`crates/gmcrypto-core/src/sm4/cbc_streaming.rs`): partial-buffer check,
`held_back?`, `strip_pkcs7_block(&last)?`, `extend_from_slice`,
`Some(mem::take(&mut self.output))`. The struct derives `Zeroize` +
`ZeroizeOnDrop` (v1.13): `cipher: Sm4Cipher` (key schedule), `prev`, `buffer`,
`buffer_len`, `output: Vec<u8>`, `held_back: Option<[u8; 16]>`. Consuming
`self` therefore puts the **zeroize-on-drop of the whole decryptor** inside the
window, plus the drop of the returned `Option<Vec<u8>>`. Production zeroization
is not bypassed or weakened for the study.

**Leak signature.** `strip_pkcs7_block` (`mode_cbc.rs`) is a 16-iteration
masked scan. The early-return control (a 6-line patch touching only that
function: `if masked != 0 { return None; }` inside the loop) exits at
iteration 0 for the `Left` class and iteration 14 for `Right`. The signature
an early-return regression would leave is therefore **≤ 14 loop iterations** of
a handful of `subtle` operations each — single-digit to low tens of
nanoseconds on this host.

**Host and timer.** Apple M1 Pro, `aarch64-apple-darwin`, macOS 27.0
(26A428), rustc 1.94.1 (e408947bf 2026-03-25), cargo 1.94.1 — all as pinned by
protocol v2. `hw.tbfrequency` = 24 000 000, so `Instant::now()` advances in
**41.67 ns ticks**; measured today, the minimum non-zero delta between
consecutive reads is 41 ns and the deltas cluster at 41/42 ns, then 83/84.
Consequences: the whole `finalize()` window is a small integer number of
ticks; the leak signature is **sub-tick**. See Q14.2 — this is the one harness
question the existing protocol does not address.

**Untimed prologue.** Per sample: draw the class from `BenchRng`, construct a
new decryptor (key schedule), absorb the 32-byte ciphertext in one `update`
(both block decrypts), place it in the slot. ~10⁵ masked operations, all
outside the window. At 20 000 samples a build's three targets take ≈ 8 s
wall-clock (protocol v2's trial).

**Research-clone identities** (commit
`c1ce4036d53fe7e3fd17b4d588e16fb3c584857b`, not on `origin`; tracked tree
verified equal to `HEAD` today; SHA-256):

| asset | path in the clone | SHA-256 |

| T1 bench (three targets; `[[bench]] f21_finalize`, `harness = false`) | `crates/gmcrypto-core/benches/f21_finalize.rs` | `2ba44c0ee2b72a6e0515144e178823c0eed4914365f7a2a860d515b7f0b3d068` |
| T2 early-return control | `research/f21/early-return.patch` | `d39ce7ddad58ad80042edb2424c41a445a56820fa175972cb58f5831d6dfb3de` |

T1's three targets: `ct_sm4_cbc_finalize` (`Left` = wrong byte at index 0,

## 3. Protocol v3 (the text that governs the measurement)

Protocol v2 (identity above) is restated here in English with one delta
(Q14.2). **Once round 1 starts, this section is frozen.** Any change means a
new version and discards every number taken under the old one. No number and
no label may be written into this file; results go to
`docs/f21-finalize-result.md` only.

**Preconditions (any mismatch → do not start).** Host, OS build, `rustc -Vv`,
`cargo -V` and the `dudect-bencher` checksum equal §2. AC power connected for
the whole run; nothing else building or benchmarking on the machine. Research
clone `HEAD` = `c1ce403…`, `git diff --quiet` and `git diff --cached --quiet`
against it both clean. `run_one`'s structure re-checked against the
checksummed crate source.

**Builds.** Three, from three separate `git archive c1ce403…` exports (never
from the index or the working tree), each with its own target directory,
pre-compiled with `cargo bench --no-run --offline --locked` before the budget
starts. `Cargo.lock` (gitignored) copied from the clone; the three copies
byte-identical, SHA-256 recorded. Per export, before compiling: SHA-256 of
`mode_cbc.rs` (unpatched value for constant-time; patched values for the
other two), of the T1 bench, and of both patches; patches applied with
`git apply` inside the export only, `--numstat` confirming they touch only
`mode_cbc.rs`. The clone's own `crates/` is never written.

**Pre-check (v3 delta, Q14.2).** Before round 1, on the constant-time build,
one recorded run of a standalone timer program (research clone only, SHA-256
recorded in the result): (a) the `Instant::now()` tick by the minimum
non-zero delta over ≥ 10⁶ consecutive reads; (b) 20 000 timings each of the
`f21_wrapper_only` closure and the `ct_sm4_cbc_finalize` closure on `Right`
inputs, reporting min / median / mean in ns and in ticks. Not part of the five
rounds; produces no label; ≤ 10 min. Its only use is the annotation in
"Criteria".

**Runs.** `DUDECT_SAMPLES=20000` (explicit, every run) `cargo bench --offline
--locked -p gmcrypto-core --bench f21_finalize`, all three targets, no
`--filter`. Five rounds; each round in the fixed order constant-time →
early-return → amplified; 15 runs, strictly sequential. No warm-up round, no
added rounds, no reordering, no re-run of a single run, no exclusion of a
round. Seeds printed by the harness are saved with the output.

**Observables.** Per run, the full console output, and per target: round,
build, target, printed `max t` and `tau` verbatim, wall-clock, exit status,
`DUDECT_SAMPLES`, seed. Once: everything under Preconditions, plus the
pre-check output, start and end time. Derived mechanically from
`ct_sm4_cbc_finalize`, nothing else: constant-time max and median `|tau|` over
five rounds; early-return per-round `|tau|` and median; amplified per-round
`|tau|`. Median of five = the third sorted value; no mean, no trimming, no
outlier removal. `max t` is recorded, never judged.

**Criteria (fixed before any number exists; thresholds 1.0, 0.20, 3×).**
After all five rounds, in order, exactly one label:

1. **Validity.** Amplified `ct_sm4_cbc_finalize` `|tau| > 1.0` in every
   round **and** `negative_control` `|tau| > 1.0` in every run; otherwise
   **`invalid-path`** — the amplified leak did not reach the window or the
   harness is not alive; the other builds' numbers are not interpreted.
2. **Distinguishable.** Valid, and every early-return round's `|tau|` exceeds
   the constant-time maximum, and early-return median ≥ 3 × constant-time
   median → **`distinguishable-on-this-host`**.
3. Otherwise **`still-blind`**.

Annotations (not labels; may accompany any label): *noise-dominated* if
constant-time `f21_wrapper_only` reads `|tau| > 0.20` in any round;
*sub-tick regime* (v3) if the pre-check median `ct_sm4_cbc_finalize` window is
≤ 2 ticks. Only the three labels exist; no "near", "tends to", or new label.

**Budget.** 30 minutes from the start of round 1 to the end of round 5;
pre-compilation, identity checks and the pre-check are outside it. Over budget
or any mid-run failure (non-zero exit, panic, a recompile, AC power lost, an
identity mismatch): stop, keep every completed run's output, **no label**. A
restart is the whole protocol from round 1, noted as such; earlier partial
data is kept, never merged.

**Applicability.** Every label is about this host, OS, toolchain, harness,
baseline and build identities, and these inputs only.
`distinguishable-on-this-host` says the narrow window separates an early-return
regression from the shipping implementation *here*; it is not a constant-time
claim about `strip_pkcs7_block` or SM4-CBC. `still-blind` says it did not
separate them here; it proves neither undetectability nor safety.
`invalid-path` says nothing about the implementation. The protocol adds,
enables or promotes no CI gate, changes no product code, zeroization, API,
dependency or version, and by itself closes nothing. Key, IV and plaintexts are
fixed public research samples.

## 4. Forks

### Q14.1 — What v1.14 is

An **assurance cycle**: execute §3, record one label, act on it per Q14.6.
Alternatives: fold the study into a later feature cycle (it would sit behind
that cycle's schedule and pins for no gain); or leave F21 open indefinitely
(the backlog line then means nothing). **Recommendation: assurance cycle, this
one item.** Workspace version stays `1.13.0`; no CHANGELOG entry; no publish.

### Q14.2 — Timer quantization (the v3 delta)

`Instant::now()` on the pinned host advances in 41.67 ns ticks (§2). The
window under study is a few ticks; the leak signature is ≤ 14 loop
iterations — sub-tick. Protocol v2's thresholds were set without this fact.
With effectively uniform phase between call start and tick boundary, the mean
of quantized readings is unbiased, so a sub-tick shift *can* surface in a
Welch t-test at 20 000 samples — but variance rises and a `still-blind` result
would otherwise be unattributable between "the strip is invisible" and "the
timer cannot see it". Options: (a) proceed under v2 and argue afterwards
(exactly the post-hoc move Q10.6 forbids); (b) look for a finer clock
(`cntvct` is the same 24 MHz source; PMU cycle counters need kernel access;
hosted Linux runners have ns-resolution TSC but are excluded — heterogeneous
SKUs, no self-hosted runner on a public repo); (c) add the recorded pre-check
and the *sub-tick regime* annotation, keeping labels and thresholds unchanged.
**Recommendation: (c).** It changes no criterion, costs ≤ 10 minutes, and is
written before any number exists. If the pre-check shows the median window
< 1 tick, the run still proceeds under §3; the annotation carries that fact
into the result.

### Q14.3 — Which protocol text governs

v2 (SHA in §2, Chinese, untracked in the research clone) restated as v3 in
§3, in this repository's language, with the Q14.2 delta. No number was ever
taken under v2, so nothing is invalidated. **Recommendation:** §3 governs; the
result cites `docs/v1.14-scope.md` §3 and records v2's SHA as provenance.

### Q14.4 — What goes upstream, and when

- **This PR:** the spec (this file) and the `CLAUDE.md` current-cycle block.
- **After measurement:** `docs/f21-finalize-result.md` — the raw console
  outputs (verbatim), every identity check, the pre-check output, the derived
  values, the label, the annotations, and the reviewer's verdict.

- **Not this cycle:** the T1 bench. No workflow would run it; a fourth
  `[[bench]]` is surface without a gate; `.claude/rules/dudect.md` forbids

**Recommendation:** as listed.

### Q14.5 — Execution and review

One agent session executes §3 as a fixed script — pre-compile, identity
checks, pre-check, 15 runs, save everything — with no discretion during the
run. One independent reviewer checks, from the saved outputs (not by
re-running): the class split and inputs match §2; the window contents match
§2; every precondition was recorded; the criteria were applied mechanically;
the label and annotations follow. Review items are resolved (fixed or declined
with a reason) before the result PR; the maintainer sees the label and one
line of review outcome. Budget: pre-check ≤ 10 min, rounds ≤ 30 min, at most
one restart in this cycle. **Recommendation:** as stated; the reviewer gets
logs, never a re-run request.

### Q14.6 — Outcomes committed in advance

Written before the first run. All four are acceptable ends of this cycle:

- **(a) `invalid-path`** → F21 stays open. Result doc records the negative;
  the `CLAUDE.md` backlog line gains "narrow-window harness path invalid on
  the pinned host (v1.14)". The only remaining avenue is a harness-side change
  (a runner that times inside the closure, or a different timer) — out of
  scope, needs its own spec.
- **(b) `distinguishable-on-this-host`** → F21 stays open, **re-scoped**: the
  narrow window is a usable research instrument on this host. Still not a CI
  gate, not promoted, not a constant-time claim; `SECURITY.md` unchanged. A
  later cycle may consider a nightly telemetry target only after the runner
  calibration conditions in `.claude/rules/dudect.md` are met.
- **(c) `still-blind`** → F21 **closes as a documented negative**: "narrow
  window blind on the pinned host under protocol v3". The backlog line is
  removed; `.claude/rules/dudect.md`'s F21 line becomes a one-line pointer to
  the result doc; `SECURITY.md` unchanged (no coverage claim either way).
- **(d) no label** (budget or mid-run failure, after the one allowed restart)
  → result doc records the incomplete runs; F21 stays open with "not measured
  within budget (v1.14)"; no further attempt this cycle.

**Recommendation:** commit to all four now; the result PR applies the matching
one and nothing else.

## 5. Assurance

- No source change under `crates/`, no `Cargo.toml` change, no workflow
  change; the dudect gates and their fingerprints are untouched.
- Disclosure boundary: `check_disclosure_boundary.py --worktree` and
  `--range origin/main..HEAD` clean at P1 on this PR and on the result PR. No
  host path, user name or session identifier appears in either document;
  research assets are identified by commit and SHA-256 only.
- The leaky builds exist only as `git archive` exports in temporary
  directories during the run and are identified by patch SHA; they are never
  committed anywhere.
- The pre-committed criteria make the result PR a mechanical application of
  §3; a reviewer can verify it from the saved outputs alone.

## 6. Risks

- **Host drift** (OS or toolchain update before the run) → precondition
  mismatch → do not start; re-pin needs a new protocol version.
- **Quantization** → Q14.2; the annotation, not a label, carries it.
- **Adaptive temptation** — widening the window, adding rounds, re-running a
  bad round. §3 forbids all of it after round 1; Q10.6 is the precedent.
- **Clone integrity** — the research clone has an untracked protocol file and
  a `Cargo.lock` outside the commit; §3's export-and-hash discipline keeps
  them out of the builds or pins them.
- **Reviewer budget** — the review is over saved logs, not a re-run; the
  result doc must be complete enough for that.

## 7. Out of scope

AVX-512 `sbox_x64`; `noise_twin_class_split` as a gate; any harness
modification or fork of `dudect-bencher`; any API, zeroization or dependency
change; any CI gate, promotion or `SECURITY.md` coverage statement; measuring
on hosted runners or any other host.
