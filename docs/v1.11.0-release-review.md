# v1.11.0 release review checklist (three-crate workspace)

The reviewer runbook for the **1.11.0** publish. Adapted from
`docs/v1.9.1-release-review.md`, with one structural difference: 1.9.1 was a
**behavior-free packaging patch**, so its headline check was "is the licence text
actually in the archive?". 1.11.0 is an **additive feature release**, so the
headline check is "is it genuinely additive, and is the default build genuinely
unchanged?".

**Publish order is `gmcrypto-simd` → `gmcrypto-core` → `gmcrypto-c`.** The
intra-workspace path-deps are pinned exactly (`=1.11.0`), so each crate must be
live on crates.io before the next resolves.

**`cargo publish` and the SSH-signed tag are the maintainer's authenticated call,
never the agent's.**

## Sequencing note — 1.9.1 first

At the time of writing, crates.io max is **1.9.0** for all three crates, and
**1.9.1 is verified GO but unpublished** (`docs/v1.9.1-release-review.md`,
candidate `530013b`). The maintainer's decision is to ship 1.9.1 first, then
1.11.0.

That ordering matters for one reason worth stating plainly: 1.9.1's only delta
from 1.9.0 is the licence-text packaging fix, with zero runtime change, so it
gives 1.9.0 consumers a risk-free path to licence text without taking the v1.11
feature surface. **Every published version through 1.9.0 shipped no licence text
at all**, and published versions are immutable — so 1.9.1 remains worth shipping
on its own even though 1.11.0 also carries the fix.

If 1.9.1 is ever abandoned, this release still closes the licence defect (see §3);
nothing in this runbook depends on 1.9.1 having shipped.

## 0. Provenance — what changed, and why it is additive

```bash
git log --oneline v1.9.0..HEAD
git diff v1.9.0..HEAD --stat -- crates/gmcrypto-core/src crates/gmcrypto-simd/src
```

Expect two categories and nothing else:

1. **v1.10 (assurance, non-publishing)** — F16 gmssl interop wired into CI, Tier-A
   fuzz census 30 → 32, the PKCS#7 unpad dedupe. F21 was attempted and
   deliberately **not** landed (the composite window is blind — `docs/v1.10-scope.md`
   Q10.9).
2. **v1.11 (this release)** — the `aead` 0.6 trait fit, entirely inside
   `#[cfg(feature = "aead-traits")] mod aead_impl` blocks in `mode_gcm.rs` /
   `mode_ccm.rs`.

Anything outside those two is a finding.

## 3. THE HEADLINE CHECK — additive, and the default build is untouched

**(a) `aead` must be absent from the default dependency graph.**

```bash
cargo tree -p gmcrypto-core | grep -c aead                      # MUST be 0
cargo tree -p gmcrypto-core --features aead-traits | grep aead  # aead v0.6.1
```

If `aead` appears in the default graph, the feature gating is broken and this is a
**blocker** — the "default build byte-identical" claim in the README, CHANGELOG and
CLAUDE.md would all be false.

**(b) The public API baseline must be additive.**

```bash
git diff v1.9.0..HEAD --numstat -- docs/api-baseline/
```

Expect `+96 -0` on `gmcrypto-core.txt`. **A non-zero removal count is a blocker** —
it means a breaking change slipped into a minor bump.

**(c) Licence text is still in all three archives** (carried from 1.9.1; do not
assume — the 1.9.0 defect was exactly this assumption):

```bash
for c in gmcrypto-core gmcrypto-simd gmcrypto-c; do
  echo -n "$c: "; cargo package -p $c --list 2>/dev/null | grep -c '^LICENSE-'
done
```

Each must print `2` (`LICENSE-APACHE` + `LICENSE-MIT`).

## 4. Build, test, lint, dependency policy

```bash
cargo build --workspace
cargo test --workspace            # NOT --all-targets (runs benches; CI timeout)
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
```

Per-feature clippy (match CLAUDE.md / CI):

```bash
cargo clippy -p gmcrypto-core --features digest-traits,cipher-traits --all-targets -- -D warnings
cargo clippy -p gmcrypto-core --features sm4-bitsliced --all-targets -- -D warnings
cargo clippy -p gmcrypto-core --features sm4-aead --all-targets -- -D warnings
cargo clippy -p gmcrypto-core --features sm4-xts --all-targets -- -D warnings
cargo clippy -p gmcrypto-core --features sm2-key-exchange,crypto-bigint-scalar --all-targets -- -D warnings
cargo clippy -p gmcrypto-core --features x509 --all-targets -- -D warnings
cargo clippy -p gmcrypto-core --features tlcp --all-targets -- -D warnings
cargo clippy -p gmcrypto-core --features tlcp,x509 --all-targets -- -D warnings
cargo clippy -p gmcrypto-core --features aead-traits --all-targets -- -D warnings
cargo clippy -p gmcrypto-c --all-targets -- -D warnings
```

**The `aead-traits` test leg is NOT optional and NOT covered by `--workspace`:**

```bash
cargo test -p gmcrypto-core --features aead-traits
```

`tests/rustcrypto_aead_traits.rs` is a `[[test]]` with `required-features`, so a
plain `cargo test --workspace` never builds it. Expect the 14 trait-surface tests
to run. **If this leg is skipped, the entire v1.11 surface goes untested at
release time.**

```bash
cargo generate-lockfile
cargo deny check --exclude-dev
cargo deny --features gmcrypto-core/digest-traits,gmcrypto-core/cipher-traits,gmcrypto-core/sm4-bitsliced,gmcrypto-core/sm4-bitsliced-simd,gmcrypto-core/sm4-aead,gmcrypto-core/sm4-xts,gmcrypto-core/crypto-bigint-scalar,gmcrypto-core/sm2-key-exchange,gmcrypto-core/x509,gmcrypto-core/tlcp,gmcrypto-core/aead-traits check --exclude-dev
rm -f Cargo.lock
```

`aead` must be allowlisted in `deny.toml`; it adds no new transitive deps
(`crypto-common 0.2` + `inout` arrived with the v0.11 digest/cipher migration).

## 5. MSRV reproducibility

```bash
cargo +1.85 build -p gmcrypto-core
cargo +1.85 build -p gmcrypto-core --features digest-traits,cipher-traits,sm4-bitsliced,sm4-bitsliced-simd,sm4-aead,sm4-xts,crypto-bigint-scalar,sm2-key-exchange,x509,tlcp,aead-traits
cargo build -p gmcrypto-core --no-default-features
cargo build -p gmcrypto-core --target wasm32-unknown-unknown --features aead-traits --no-default-features
```

`aead` 0.6.1 declares MSRV 1.85 — exactly ours — which is why it was admissible at
all. A 1.85 failure here is a blocker, not a warning.

## 6. API/ABI freeze — drift checks

```bash
cargo +nightly-2026-05-23 public-api --manifest-path crates/gmcrypto-core/Cargo.toml \
  --all-features --omit blanket-impls,auto-trait-impls,auto-derived-impls \
  > docs/api-baseline/gmcrypto-core.txt
git diff --exit-code docs/api-baseline/

cargo semver-checks check-release -p gmcrypto-core   # enforced from 1.0
cargo build -p gmcrypto-c --features regen-header
git diff --exit-code crates/gmcrypto-c/include/gmcrypto.h
```

The C ABI is **unchanged** by v1.11 — the `aead` traits are Rust traits with no
meaningful FFI representation, so the header must not move. Entry-point count
stays **104**.

## 7. Runtime correctness — default build byte-identical to 1.9.0

```bash
cargo test --workspace
GMCRYPTO_GMSSL=1 cargo test --test interop_gmssl                      # 11
GMCRYPTO_GMSSL=1 cargo test --test interop_gmssl --features sm4-aead  # 13
```

The interop suite pins its oracle version and fails with `ORACLE DRIFT` on any
build other than GmSSL 3.2.0 — that is the harness working, not a finding. Needs
GmSSL 3.2.0 on `PATH`; CI's `interop-gmssl` job covers it against a pinned
from-source build.

## 8. Constant-time harness

```bash
DUDECT_SAMPLES=10000 cargo bench --bench timing_leaks \
  --features sm2-key-exchange,tlcp,sm4-xts,sm4-aead,sm4-bitsliced-simd,crypto-bigint-scalar
```

**Target count stays 23 — v1.11 adds none.** That is a deliberate decision, not an
oversight: `Sm4Gcm` / `Sm4Ccm` are thin wrappers, so `ct_sm4_gcm_decrypt` and
`ct_sm4_ccm_decrypt` already measure byte-identical code on the trait path. The
thinness that argument depends on is guarded by the differential fuzz target
`fuzz_sm4_aead_traits`, **not by prose** — see §9.

`negative_control` must fire (`|tau| > 1.0`); gated targets stay under `0.20`.

## 9. Fuzz census

```bash
grep -c '^\[\[bin\]\]' fuzz/Cargo.toml     # 33
cargo +nightly fuzz build
cargo +nightly fuzz run fuzz_sm4_aead_traits fuzz/corpus/fuzz_sm4_aead_traits \
    fuzz/seeds/fuzz_sm4_aead_traits -- -max_total_time=120
```

The census must be **33**, and `fuzz-nightly.yml`'s preflight enforces that
`FUZZ_TARGETS` names every `[[bin]]` — a target absent there still compiles but is
silently never fuzzed.

## 12. Publish dry-runs (in publish order)

```bash
cargo publish -p gmcrypto-simd --dry-run
cargo publish -p gmcrypto-core --dry-run   # expected to FAIL to resolve
cargo publish -p gmcrypto-c    --dry-run   # expected to FAIL to resolve
```

**Only `gmcrypto-simd` can fully dry-run.** `gmcrypto-core`'s `=1.11.0` dep on
`gmcrypto-simd` cannot resolve until simd is actually live, and `gmcrypto-c`'s on
core likewise. Those resolution failures are **the lockstep contract behaving
correctly** — not findings. Any *other* dry-run error is a finding.

## 13. The publish sequence (only after GO)

```bash
cargo publish -p gmcrypto-simd
# wait for the index to update, then:
cargo publish -p gmcrypto-core
cargo publish -p gmcrypto-c
git rev-parse HEAD                                            # MUST be the reviewed SHA
git tag -s v1.11.0 <reviewed-sha> -m "gm-crypto-rs v1.11.0"   # SSH-signed (gpg.format=ssh)
git push origin v1.11.0
gh release create v1.11.0 --title "v1.11.0" --notes-from-tag
```

**Name the reviewed SHA on the tag.** A bare `git tag -s v1.11.0` tags whatever
`HEAD` happens to be. Publish from a checkout of the reviewed commit and pass that
SHA explicitly — the published archive is immutable, so a tag ⟷ registry mismatch
is awkward to correct.
