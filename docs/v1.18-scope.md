# v1.18 scope — HKDF-SM3, SM2 keygen & streaming digest, SM4 batch fanout & zeroize sweep, C-doc hygiene

**Status:** **draft / pre-registration (2026-11-22).** Written against `main` on
the `1.17.0` line; awaits maintainer must-pin review before code
(`.claude/rules/docs-and-release.md`). Mirrors `docs/v1.13-scope.md` and
`docs/v1.16-scope.md` (why-now → structural facts → forks Q18.1–Q18.7 →
assurance → risks → out of scope → sequence).

Four core/internal workstreams plus C-doc hygiene, all **additive**, zero
breaking changes, zero new runtime dependencies, `#![no_std]` + `alloc` in
`gmcrypto-core`, `unsafe_code = "forbid"` in `gmcrypto-core`, MSRV **1.87** /
edition **2024** (`1.18.0` minor; three-crate workspace in lockstep with
`=1.18.0` sibling pins; `gmcrypto-simd` unchanged; **zero C ABI change** in
`gmcrypto-c`):

1. **W1 — HKDF-SM3** (`gmcrypto_core::kdf`): `hkdf_sm3_extract`,
   `hkdf_sm3_expand`, and `hkdf_sm3` (RFC 5869 over HMAC-SM3).
2. **W2a — `Sm2PrivateKey::generate`**: constant-time bounded-retry key
   generation (`sample_scalar_in_range` factored from `sample_nonzero_scalar`).
3. **W2b — Streaming SM2 hashing & pre-hashed signatures**: `Sm2Hasher`,
   `Sm2Digest`, `sm2::sign_digest`, and `sm2::verify_digest`.
4. **W3 — Internal SM4 SIMD batch fanout & temp-buffer zeroize sweep**:
   stack-batched `Sm4Cipher::{encrypt_blocks,decrypt_blocks}` fanout in
   `Sm4GcmEncryptor::update` and `mode_cbc::decrypt`, plus wiping four
   pre-existing unzeroized SM4 temporary buffers.
5. **C-doc hygiene (zero ABI change)**: remove false `_ctr_*` claims, update
   stale pre-1.0 prose, and align `GMCRYPTO_ERR` naming across C docs and rules.

## 1. Why now

- **KDF completeness.** `crates/gmcrypto-core/src/kdf.rs` currently ships only
  `pbkdf2_hmac_sm3` and explicitly notes that callers needing an HKDF-shaped
  extract-expand KDF for high-entropy inputs have none in this crate. Adding
  RFC 5869 HKDF-SM3 composes the existing `hmac::HmacSm3` primitive with zero
  new dependencies.
- **SM2 key generation & streaming digest.** Callers generating fresh SM2 keys
  today must write a manual CSPRNG rejection loop over
  `Sm2PrivateKey::from_bytes_be` and manually wipe the raw buffer (as shown in
  the `crates/gmcrypto-core/src/sm2/mod.rs` doctest and
  `docs/guides/sm2-keys.md`). Likewise, `sign_with_id` and `verify_with_id`
  require a contiguous `&[u8]` message slice, forcing callers with large or
  streamed payloads—or protocols that exchange a precomputed `SM3(Z_A || M)`
  digest—to buffer the entire message in memory.
- **Internal SM4 throughput & zeroization.** `Sm4GcmEncryptor::update`
  (`gcm_streaming.rs`) and single-shot `mode_cbc::decrypt` (`mode_cbc.rs`)
  still step one block at a time via `encrypt_block`/`decrypt_block` instead of
  fanning out through `Sm4Cipher::{encrypt_blocks,decrypt_blocks}` under
  `sm4-bitsliced-simd`. Separately, while v1.13 closed drop-time zeroization
  across the SM4 streaming structs, four temporary buffers in SM4 modes remain
  unzeroized (`keystream` vectors in `mode_gcm.rs`, `mode_ctr.rs`, and
  `ctr_streaming.rs`, plus decrypted `buf` on the failure path of
  `mode_cbc::decrypt`).
- **C-doc accuracy.** `crates/gmcrypto-c` still mentions nonexistent `_ctr_*`
  FFI functions in `src/lib.rs` and `include/gmcrypto.h`, carries pre-1.0
  (`v0.4`/`v0.5`) SemVer and RNG-callback prose in `README.md` and `src/lib.rs`,
  and uses `GMCRYPTO_FAILED` in several comments and rule files where the actual
  exported constant is `GMCRYPTO_ERR`.

## 2. Structural facts

**F1 — `sample_nonzero_scalar` already exists for `[1, n-1]`.**
`crates/gmcrypto-core/src/sm2/sign.rs` defines
`pub(crate) const NONCE_SAMPLE_BUDGET: usize = 4` and
`pub(crate) fn sample_nonzero_scalar<R: TryCryptoRng>(rng: &mut R) -> Option<(Fn, Choice)>`,
which checks `!candidate.ct_eq(&U256::ZERO) & candidate.ct_lt(&n)` and picks the
first valid draw via `U256::conditional_select` over 4 fixed draws. It is
called by `sign.rs` (`try_sign_once`), `encrypt.rs` (`encrypt`), and
`key_exchange.rs` (`sample_ephemeral`). By contrast, `Sm2PrivateKey`
(`private_key.rs`) enforces `d ∈ [1, n-2]` (`!d.ct_eq(&U256::ZERO) & d.ct_lt(&(n - 1))`
in `from_scalar_inner`).

**F2 — `Sm2PublicKey` has a `#[doc(hidden)]` identity-point escape hatch.**
`Sm2PublicKey::from_point(ProjectivePoint)` and `From<ProjectivePoint>` are
`#[doc(hidden)] pub` (`sm2/public_key.rs`), so `compute_z` (`sm2/sign.rs`)
panics in `to_affine().expect("public key is finite")` unless callers guard
`public.point().is_identity()` first—which is why `verify_with_id`
(`sm2/verify.rs`) and `encrypt` (`sm2/encrypt.rs`) explicitly reject the
identity point at the boundary.

**F3 — `Sm3` scrubs on `Drop` and moves by value on `finalize`.**
`Sm3` (`crates/gmcrypto-core/src/sm3.rs`) implements `Drop` manually (zeroizing
`state` and `buffer`) and does not implement `zeroize::Zeroize`;
`Sm3::finalize(mut self)` consumes `self` by value. Therefore `HmacSm3`
(`crates/gmcrypto-core/src/hmac.rs`) relies on `Sm3`'s field-layer `Drop`
rather than deriving `ZeroizeOnDrop` or implementing an outer `Drop` (which
would trigger E0509 when `finalize(self)` moves `self.inner`).

**F4 — MSRV 1.87 excludes `slice::as_chunks_mut`.**
The workspace MSRV is `1.87` (`Cargo.toml`). `slice::as_chunks` and
`slice::as_chunks_mut` stabilized in Rust 1.88, so stack-batched SM4 loops
cannot use them and must copy/slice `[[u8; BLOCK_SIZE]; BATCH]` explicitly.

**F5 — `zeroize` already enables `alloc` in `Cargo.toml`.**
Since v1.13, `zeroize = { version = "1.8.2", default-features = false, features = ["derive", "alloc"] }`
is in the workspace dependencies, so `.zeroize()` on `Vec<[u8; BLOCK_SIZE]>` and
`Vec<u8>` works directly under `#![no_std]` + `alloc` with zero Cargo.toml edits.

**F6 — The C error constant is `GMCRYPTO_ERR`, and `AGENTS.md` symlinks `CLAUDE.md`.**
`crates/gmcrypto-c/src/lib.rs` exports `GMCRYPTO_OK = 0` and
`GMCRYPTO_ERR = -1`; no `GMCRYPTO_FAILED` symbol exists. `GMCRYPTO_FAILED`
drifted into `CallbackRng` comments in `crates/gmcrypto-c/src/lib.rs`,
`.claude/rules/ffi.md`, `CLAUDE.md`, and `SECURITY.md`. At the repository root,
`AGENTS.md` is a symlink to `CLAUDE.md`, so editing `CLAUDE.md` updates both.

**F7 — Assurance gates.**
`docs/api-baseline/gmcrypto-core.txt` is drift-checked in
`.github/workflows/api-stability.yml` with pinned `cargo-public-api` `0.52.0` on
`nightly-2026-05-23`, alongside enforced `cargo-semver-checks` (`0.50.0` against
crates.io `1.17.0`). `.github/workflows/dudect-pr.yml` triggers automatically on
changes under `crates/gmcrypto-core/src/**`.

## 3. Forks and scope decisions

### Q18.1 — Core-first `v1.18` (1.x FFI discipline)

**Decision:** `v1.18` ships the core primitives (W1, W2a, W2b), internal SM4
SIMD fanout and zeroization sweep (W3), and C-doc cleanup (**zero C ABI
change**).

- **Deferred to `v1.19`:** C ABI parity (`gmcrypto_hkdf_sm3_*`,
  `gmcrypto_sm2_privkey_generate` / `gmcrypto_sm2_privkey_generate_with_rng` +
  `gmcrypto_sm2_privkey_public_key`, `gmcrypto_sm2_hasher_*` + digest
  sign/verify, and `gmcrypto_sm4_ctr_*`), following the established Rust-first,
  C-ABI-next-cycle rule (`v0.9→v0.10`, `v1.1→v1.2`, `v1.3→v1.4`, `v1.12→v1.13`).
- **Deferred to `v1.19`:** compressed SEC1 support (`N1`), strictly additive
  `Sm2PublicKey::to_sec1_compressed` / `Sm2PublicKey::from_sec1_compressed`
  without widening `Sm2PublicKey::from_sec1_bytes` or `spki::decode`.
- **Deferred to `v1.19+`:** PKCS#10 CSR (`N2`, currently listed out of scope in
  `SECURITY.md`) and `signature-traits` (`N3`).

### Q18.2 — W1 HKDF-SM3 (`gmcrypto_core::kdf`)

**Decision:** implement RFC 5869 HKDF over HMAC-SM3 (`HmacSm3` / `hmac_sm3`) in
`crates/gmcrypto-core/src/kdf.rs`:

```rust
#[must_use]
pub fn hkdf_sm3_extract(salt: &[u8], ikm: &[u8]) -> [u8; 32]
#[must_use]
pub fn hkdf_sm3_expand(prk: &[u8; 32], info: &[u8], output: &mut [u8]) -> Option<()>
#[must_use]
pub fn hkdf_sm3(salt: &[u8], ikm: &[u8], info: &[u8], output: &mut [u8]) -> Option<()>
```

- **`hkdf_sm3_extract`:** treats an empty `salt` as `[0u8; 32]` (`DIGEST_SIZE`
  zeros) per RFC 5869 §2.2; empty `ikm` is permitted; returns `HMAC-SM3(salt', ikm)`.
- **`hkdf_sm3_expand`:** takes a typed 32-byte `&[u8; 32]` PRK (`DIGEST_SIZE`).
  Returns `None` on `output.is_empty()` or `output.len() > 255 * 32` (`8160`
  bytes) **before modifying `output`**. Empty `info` is permitted. Computes
  `T(i) = HMAC-SM3(PRK, T(i-1) || info || [i as u8])` sequentially using
  streaming `HmacSm3::new(prk)` (`T(0)` empty) with zero heap allocation,
  writing into `output` in up to 32-byte chunks and zeroizing the rolling
  `T(i)` buffer before return.
- **`hkdf_sm3`:** checks the output-length bounds (`None` without touching
  `output`), runs `hkdf_sm3_extract`, expands via `hkdf_sm3_expand`, and
  zeroizes the intermediate `prk` before returning `Some(())`.
- **Docs & rules:** update `crates/gmcrypto-core/src/kdf.rs` module docs
  (currently stating "`pbkdf2_hmac_sm3` is the only one" / "does not ship one")
  and `.claude/rules/sm2-sm3.md` (`kdf.rs` note).
- **Independent oracle & gates:** cross-validate with KAT vectors generated
  from OpenSSL 3+/4 (`openssl kdf -kdfopt digest:SM3 ... HKDF`) covering
  RFC 5869 test-case shapes (standard inputs, long IKM/salt/info/output, empty
  salt/info, empty IKM, `8160`-byte max boundary, extract-only, expand-only).
  No new dudect target (composes `HmacSm3` over public lengths, matching the
  v1.6 `tlcp::key_schedule` posture in `SECURITY.md`) and no new fuzz target
  (typed inputs, not an untrusted-input decoder).

### Q18.3 — W2a `Sm2PrivateKey::generate`

**Decision:** add `Sm2PrivateKey::generate` in
`crates/gmcrypto-core/src/sm2/private_key.rs` and factor the shared bounded
constant-time sampler:

```rust
pub fn generate<R: TryCryptoRng>(rng: &mut R) -> Result<Self, crate::Error>
```

- **Shared sampler:** generalize `sample_nonzero_scalar` in
  `crates/gmcrypto-core/src/sm2/sign.rs` into
  `pub(crate) fn sample_scalar_in_range<R: TryCryptoRng>(rng: &mut R, upper_exclusive: &U256) -> Option<(Fn, Choice)>`.
  It unconditionally runs `NONCE_SAMPLE_BUDGET = 4` iterations, checks
  `!candidate.ct_eq(&U256::ZERO) & candidate.ct_lt(upper_exclusive)`, selects the
  first valid candidate via `subtle::ConditionallySelectable`
  (`conditional_select` / `conditional_assign`), and unconditionally zeroizes
  both per-iteration `buf` and `chosen` (including on RNG error).
- **Range split:** `Sm2PrivateKey::generate` passes
  `upper_exclusive = n - 1` so keys sample `[1, n-2]` (matching
  `Sm2PrivateKey::from_scalar_inner`). `sample_nonzero_scalar` wraps
  `sample_scalar_in_range(rng, Fn::MODULUS.as_ref())` so `sign.rs`, `encrypt.rs`,
  and `key_exchange.rs` continue sampling `[1, n-1]`.
- **Constant-time finish & failure collapse:** `generate` computes
  `let public = mul_g(&d)` unconditionally before inspecting `sample_ok`, wipes
  `d` if `!bool::from(sample_ok)`, and collapses both RNG failure and budget
  exhaustion (`~2^-128` for a uniform CSPRNG) to `Err(crate::Error::Failed)`.
- **Docs:** update `crates/gmcrypto-core/src/sm2/mod.rs` (`# Generating a key
  and encrypting` doctest), `Sm2PrivateKey` docs in `private_key.rs`, and
  `docs/guides/sm2-keys.md` to use `Sm2PrivateKey::generate` instead of a manual
  rejection loop.

### Q18.4 — W2b Streaming `Sm2Hasher` / `Sm2Digest` + `sign_digest` / `verify_digest`

**Decision:** place `Sm2Hasher`, `Sm2Digest`, and `sign_digest` in `sm2::sign`
(`crates/gmcrypto-core/src/sm2/sign.rs`), `verify_digest` in `sm2::verify`
(`crates/gmcrypto-core/src/sm2/verify.rs`), and re-export all four at
`gmcrypto_core::sm2::*`:

```rust
pub struct Sm2Hasher { inner: Sm3 }
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub struct Sm2Digest([u8; 32]);

impl Sm2Hasher {
    #[must_use]
    pub fn new(public: &Sm2PublicKey, id: &[u8]) -> Option<Self>;
    #[must_use]
    pub fn new_default_id(public: &Sm2PublicKey) -> Option<Self>;
    pub fn update(&mut self, data: &[u8]);
    #[must_use]
    pub fn finalize(self) -> Sm2Digest;
}

impl Sm2Digest {
    #[must_use]
    pub const fn as_bytes(&self) -> &[u8; 32];
    #[must_use]
    pub const fn from_precomputed_z_hash(e: [u8; 32]) -> Self;
}

pub fn sign_digest<R: TryCryptoRng>(
    key: &Sm2PrivateKey,
    digest: &Sm2Digest,
    rng: &mut R,
) -> Result<Vec<u8>, crate::Error>;

#[must_use]
pub fn verify_digest(
    public: &Sm2PublicKey,
    digest: &Sm2Digest,
    sig_der: &[u8],
) -> bool;
```

- **Safe identity invariant on `Sm2Hasher`:** both `Sm2Hasher::new` and
  `Sm2Hasher::new_default_id` (which delegates to `Self::new(public, DEFAULT_SIGNER_ID)`)
  return `Option<Self>`. Because `#[doc(hidden)] Sm2PublicKey::from_point` can
  wrap `ProjectivePoint::identity()` (F2), checking
  `!bool::from(public.point().is_identity())` (and `id.len() <= MAX_ID_LEN`) in
  both constructors eliminates any panic inside `compute_z`'s
  `to_affine().expect(...)` and guarantees every live `Sm2Hasher` holds a
  valid `Z_A`-prefixed `Sm3` state. Any public key from `Sm2PrivateKey::public_key`
  or `Sm2PublicKey::from_sec1_bytes` yields `Some`.
- **Zeroization on `Sm2Hasher`:** follows `HmacSm3` (F3)—relies on the inner
  `Sm3`'s `Drop` impl to scrub `state` and `buffer` on early drop and after
  `finalize(self)` without an outer `impl Drop` / `ZeroizeOnDrop` that would
  conflict with moving `self.inner` into `Sm3::finalize`. Document this
  best-effort field-layer zeroization posture on `Sm2Hasher`.
- **Loud escape-hatch warning on `Sm2Digest::from_precomputed_z_hash`:** docs
  must state explicitly that `e` **MUST** be `SM3(Z_A || M)`, **never** raw
  `SM3(M)`, because omitting `Z_A` breaks GB/T 32918.2 signer-ID and public-key
  binding. Likewise, `sign_digest` documents that it cannot verify `digest` was
  computed under `key.public_key()`'s `Z_A`.
- **Shared signing/verification cores:** extract
  `pub(crate) fn sign_raw_digest` (not `#[doc(hidden)] pub`, leaving
  `sign_raw_with_id` as the sole dudect entry point per `.claude/rules/sm2-sm3.md`)
  carrying the `SIGN_RETRY_BUDGET = 2` masked-select loop shared by
  `sign_raw_with_id` and `sign_digest`. `verify_digest` retains the
  `public.point().is_identity()` guard, DER decode, `r, s ∈ [1, n-1]`,
  `t = (r + s) mod n != 0`, and `(x1, _) = s·G + t·P` check; `verify_with_id`
  delegates to `verify_digest` via `Sm2Hasher`.

### Q18.5 — W3 SM4 SIMD batch fanout + unzeroized temp-buffer sweep (internal-only)

**Decision:** zero public API change; MSRV 1.87 compliant (no
`slice::as_chunks_mut` per F4).

1. **Stack-batched SIMD fanout (`const BATCH: usize = 16`, 256 bytes):**
   - `Sm4GcmEncryptor::update` (`crates/gmcrypto-core/src/sm4/gcm_streaming.rs`):
     drain full blocks (after any `self.ks` leftover drain) in batches of up to
     `BATCH` blocks, advancing `self.counter` via `inc32`, calling
     `self.cipher.encrypt_blocks(&mut ks_batch[..n])`, XORing into `out`, and
     calling `ks_batch.zeroize()` before returning or proceeding to the tail.
   - `mode_cbc::decrypt` (`crates/gmcrypto-core/src/sm4/mode_cbc.rs`): process
     `buf` in chunks of up to `BATCH * BLOCK_SIZE`, snapshotting ciphertext
     blocks into `saved`, decrypting `pt_batch` via
     `cipher.decrypt_blocks(&mut pt_batch[..n])`, XORing block `0` with `prev`
     and block `k` with `saved[k - 1]`, updating `prev` from `saved[n - 1]`,
     writing plaintext back to `buf`, and calling `pt_batch.zeroize()`.
2. **Zeroize the four pre-existing unzeroized SM4 temporary buffers (F5):**
   - `mode_gcm::gctr` (`crates/gmcrypto-core/src/sm4/mode_gcm.rs`):
     `keystream.zeroize()` before return.
   - `mode_ctr::apply_keystream` (`crates/gmcrypto-core/src/sm4/mode_ctr.rs`):
     `keystream.zeroize()` before return.
   - `Sm4CtrCipher::update` (`crates/gmcrypto-core/src/sm4/ctr_streaming.rs`):
     `keystream.zeroize()` after the full-block batch XOR.
   - `mode_cbc::decrypt` (`crates/gmcrypto-core/src/sm4/mode_cbc.rs`): when
     `strip_pkcs7_ct(&mut buf)` returns `None`, call `buf.zeroize()` before
     returning `None`.

## 5. Risks

- **`Sm2Digest::from_precomputed_z_hash` misuse.** A caller passing raw `SM3(M)`
  instead of `SM3(Z_A || M)` bypasses signer-ID and public-key binding.
  Mitigation: explicit function name (`from_precomputed_z_hash`) plus loud doc
  warnings on both `from_precomputed_z_hash` and `sign_digest`.
- **`Sm2Hasher` E0509 trap.** Deriving `ZeroizeOnDrop` on `Sm2Hasher` would
  forbid `finalize(self)` from moving `self.inner` into `Sm3::finalize`.
  Mitigation: rely on `Sm3`'s existing field-layer `Drop` (F3, `HmacSm3`
  precedent).
- **Post-1.87 API slip in W3.** Using `slice::as_chunks_mut` would compile on
  newer toolchains and break `+1.87`. Mitigation: plain block indexing/copying
  and running the `+1.87` build leg locally before opening each PR.
- **CBC decrypt batch chaining bug or `Sm4GcmEncryptor` leftover drift.**
  Mitigation: snapshot ciphertext blocks before `decrypt_blocks` (`prev` →
  `saved[n-1]`), keep `Sm4GcmEncryptor` `self.ks` / `self.ks_pos` drain/tail
  logic intact, and test block counts straddling `BATCH = 16` across all cipher
  feature legs.
- **Unintended C ABI diff or dudect noise from W3.** Mitigation: inspect `git
  diff crates/gmcrypto-c/include/gmcrypto.h` to verify comment-only changes, and
  read `RUNNER-CPU:` first if PR dudect smoke shifts from added zeroization
  memsets.

## 6. Out of scope

- Any C ABI additions or symbol changes (deferred to `v1.19`: `gmcrypto_hkdf_sm3_*`,
  `gmcrypto_sm2_privkey_generate[_with_rng]`, `gmcrypto_sm2_privkey_public_key`,
  `gmcrypto_sm2_hasher_*`, `gmcrypto_sm4_ctr_*`).
- Compressed SEC1 (`N1`: `Sm2PublicKey::{to_sec1_compressed,from_sec1_compressed}`,
  deferred to `v1.19`).
- PKCS#10 CSR (`N2`) and `signature-traits` (`N3`) (deferred to `v1.19+`).
- Widening `Sm2PublicKey::from_sec1_bytes` or `spki::decode`, adding a custom
  `gmcrypto-core` RNG dependency, or any breaking change to `1.x` APIs.
