# v1.19 scope — C ABI parity, SM4-CTR and compressed SEC1 public keys

**Scope approved by the maintainer on 2026-11-22.** The
published baseline is `v1.18.0` (`d6a6a9e`). That release added HKDF-SM3,
SM2 key generation and identity-bound streaming signatures in Rust. Rust
already supports single-shot and streaming SM4-CTR. The v1.19 release will expose
those operations in the default C library and add two compressed-point methods
to the default Rust API. [v1.18 scope, Q18.1](v1.18-scope.md#q181--core-first-v118-1x-ffi-discipline)

## Maintainer sign-off

The maintainer approved Q19.1–Q19.6 as proposed, including the pointer and
ownership contracts below. [Approval on PR #284](https://github.com/frankxue831/gm-crypto-rs/pull/284#issuecomment-7081050697)

| Decision | Approved contract |
|---|---|
| Q19.1 · HKDF-SM3 | Use disjoint buffers and PBKDF2-style `(out, out_len)` for expand and one-shot. Reject invalid lengths before writing. Wipe temporary PRK copies in the shim. |
| Q19.2 · SM2 key ownership and RNG | Use pointer-returning key constructors and the existing RNG callback. Derivation returns an independently owned `gmcrypto_sm2_pubkey_t *`. |
| Q19.3 · SM2 digest and signer ID | Return a caller-owned 32-byte digest. Separate default-ID and explicit-ID constructors. The explicit constructor accepts both zero-length pointer forms. Finalize frees a valid handle even on output error. |
| Q19.4 · SM4-CTR symbols | Supply named encrypt and decrypt one-shots and one bidirectional streaming handle. Freeing the stream completes it. |
| Q19.5 · SM4-CTR buffers | Require disjoint buffers. Check output pointers and capacity before calling Rust. A short buffer reports the required length and leaves the stream retryable. |
| Q19.6 · Compressed SEC1 | Add two explicit Rust methods for bare SM2 public keys. Existing point parsers and C functions keep their uncompressed contracts. |

## C contracts

The 1.18.0 header has 112 entry points. The approved scope adds 19.
Use the existing C success/failure conventions. Status functions
return `GMCRYPTO_OK` or `GMCRYPTO_ERR`, fallible constructors return an owned
handle or `NULL`, and each `_free(NULL)` is a no-op. Retain panic containment
at the ABI boundary. [1.18.0 C header](https://github.com/frankxue831/gm-crypto-rs/blob/v1.18.0/crates/gmcrypto-c/include/gmcrypto.h)

**Q19.1 · HKDF-SM3.** `gmcrypto_hkdf_sm3_extract` writes a 32-byte PRK.
`gmcrypto_hkdf_sm3_expand` and `gmcrypto_hkdf_sm3` take `(out, out_len)`.
Empty salt, input key material and info are valid, including `(NULL, 0)`.
Empty salt means 32 zero bytes. The Rust API accepts output lengths 1 through
8160. Reject other lengths before writing, including when the caller provided
a valid buffer. Callers wipe their secret buffers. The shim must wipe any
temporary PRK copies it creates. [Rust KDF](../crates/gmcrypto-core/src/kdf.rs) · [RFC 5869 §2](https://www.rfc-editor.org/rfc/rfc5869#section-2)

**Q19.2 · SM2 keys.** `gmcrypto_sm2_privkey_generate` uses the system RNG.
`gmcrypto_sm2_privkey_generate_with_rng` uses the existing
`gmcrypto_rng_callback` and context. Both delegate to the core's bounded
sampler for signing keys in `[1, n−2]`. RNG failure, a missing callback on the
callback entry point, or sampler exhaustion returns `NULL`.
`gmcrypto_sm2_privkey_public_key` borrows the private handle for the call.
The returned public handle remains usable after the private handle is freed.
[Rust key generation](../crates/gmcrypto-core/src/sm2/private_key.rs)

**Q19.3 · SM2 streaming and precomputed digests.** Under the
`gmcrypto_sm2_hasher_` prefix, `new(public_key)` selects `DEFAULT_SIGNER_ID`
and `new_with_id(public_key, id, id_len)` uses the exact supplied ID.
Existing message-level C signing interprets a zero-length ID as the default.
The explicit-ID constructor hashes a literal empty ID for both `(NULL, 0)`
and `(non-null, 0)`.
Both constructors bind the key and ID immediately. `update` accepts message
chunks, including an empty chunk. `finalize` consumes and frees a valid handle
even on output error and writes 32 bytes on success. `free` aborts a live
hasher. The caller uses exactly one terminal operation.

The functions `gmcrypto_sm2_sign_digest`, `gmcrypto_sm2_sign_digest_with_rng`
and `gmcrypto_sm2_verify_digest` accept a fixed 32-byte
`e = SM3(Z_A || M)`. Document that formula prominently in `gmcrypto.h` at the
digest entry points. A caller supplying a precomputed digest owns its key and
signer-ID binding. The shim cannot establish that binding from bytes.
Signing uses the existing DER signature output convention
`(out, capacity, actual_len)`. Verification returns the same error for a
mismatch and malformed DER. [Rust digest contract](../crates/gmcrypto-core/src/sm2/sign.rs) · [C message-level conventions](../crates/gmcrypto-c/src/lib.rs)

**Q19.4–Q19.5 · SM4-CTR.** `gmcrypto_sm4_ctr_encrypt` and
`gmcrypto_sm4_ctr_decrypt` wrap the existing Rust mode.
`gmcrypto_sm4_ctr_cipher_new`, `gmcrypto_sm4_ctr_cipher_update` and
`gmcrypto_sm4_ctr_cipher_free` wrap one `Sm4CtrCipher`. The caller supplies
a 16-byte key and 16-byte initial counter. The full counter increments as a
big-endian integer modulo 2¹²⁸. The caller must allocate disjoint counter
ranges under each key. CTR supplies confidentiality only.

Each successful call emits exactly the input length. A partial block carries
its unused keystream into the next update. Use `(out, capacity, actual_len)`.
With a valid length pointer, an empty update accepts empty buffers and reports
zero. On a short buffer, report the required byte count, write no payload and
leave the counter and leftover bytes intact. Check `actual_len`, the output
pointer for nonempty output, and capacity before invoking the Rust update.
Require disjoint input and output storage for nonempty calls.
[Rust CTR](../crates/gmcrypto-core/src/sm4/mode_ctr.rs) · [Streaming CTR](../crates/gmcrypto-core/src/sm4/ctr_streaming.rs)

## Q19.6 · Strictly additive compressed SEC1

Add `Sm2PublicKey::to_sec1_compressed(&self) -> [u8; 33]` and
`Sm2PublicKey::from_sec1_compressed(bytes: &[u8]) -> Option<Self>`. A finite
point encodes as `02 || X` for even affine Y and `03 || X` for odd affine Y,
with X in 32-byte big-endian form. Like `to_sec1_uncompressed`, the encoder
panics on an identity constructed through the hidden low-level API.
Decode exactly 33 bytes, check `X < p`
before field reduction, recover a square root of the curve equation and
verify the square and requested parity. The SM2 prime permits the fixed
public exponent `(p+1)/4`. Reject non-residues, infinity, hybrid encodings
and every other malformed input with `None`. Keep field helpers private.
[SEC 1 v2.0 §§2.3.3–2.3.4](https://www.secg.org/sec1-v2.pdf#page=16)

The existing `from_sec1_bytes` and `spki::decode` continue to require an
uncompressed point. This preserves SPKI/X.509, embedded public keys in
SEC1/PKCS#8, key-exchange points and ciphertext layouts. The C constructor
`gmcrypto_sm2_pubkey_new` reads a fixed 65 bytes. A 33-byte allocation is
invalid input to that function. Compressed C import/export is deferred.
[Rust public keys](../crates/gmcrypto-core/src/sm2/public_key.rs) · [SPKI decoder](../crates/gmcrypto-core/src/spki.rs)

## Acceptance and sequence

Land the C KDF and key constructors, then the SM2 digest and
CTR wrappers in reviewable families. The Rust SEC1 addition can be reviewed
independently. Each implementation PR carries the tests for its own contract.

| Surface | Evidence needed before completion |
|---|---|
| HKDF | Compare extract, expand and one-shot through C against the existing OpenSSL-verified vectors. Include empty inputs, output lengths 0, 1, 8160 and 8161, and a sentinel proving rejected lengths leave the output untouched. |
| SM2 keys and signatures | Use a scripted RNG for a known key, callback failure and all-invalid draws. Use the public handle after freeing the private handle. Cross-verify streamed and one-shot C signatures in both directions for default and nonempty IDs. Compare DER under a fixed signing nonce. Check both empty-ID pointer forms against Rust's literal empty ID and distinguish them from the default. Exercise the 8191/8192-byte ID boundary, wrong ID/key, plain `SM3(M)` against message verification, malformed DER, failed finalize and abort. |
| CTR | Compare C one-shot and chunked operation in both directions against the existing ECB-derived vectors and GmSSL interop coverage. Exercise zero length, splits around 16 bytes, counter carry across 32 bits and full-width wrap. Mid-block, exercise a null output for nonempty input, a null length pointer, and a short buffer. Retry with valid storage and compare subsequent output to an uninterrupted stream. |
| SEC1 | Pin independently verified encodings for G and −G (same X, opposite prefix). Check both round trips, wrong lengths/tags, X ≥ p and a non-residue. The legacy point parser must reject a valid 33-byte key. The SPKI decoder must reject an otherwise valid DER structure containing that key in its subjectPublicKey BIT STRING. Extend `fuzz_sm2_pubkey_sec1` with both prefix seeds and require exact re-encoding of every accepted compressed input. |

Exercise every new C symbol in `c_smoke`, regenerate and drift-check
`gmcrypto.h`, compile C examples and reconcile documented symbol/test counts.
Check that the released C declarations still compile and the reviewed symbol
list contains only additions. Regenerate the pinned Rust API baseline, check
SemVer against 1.18.0, and run the existing timing, MSRV 1.87 and `no_std`
checks on the changed core paths. The design uses existing runtime dependencies
and retains the core's `unsafe_code = "forbid"` policy. PKCS#10 CSR and
RustCrypto signature traits remain future scope.

A later release-prep PR owns the lockstep version bump and fresh downstream
Gate #1 evidence for the candidate. The 1.18 result covers the earlier code.
