# v1.15 structural control-build qualification

Build-only preparation under [protocol §5](v1.15-protocol.md), completed
2026-09-28. All four feature legs compiled the unmodified harness and all
20 control recipes; all 80 untimed control checks passed. Inspection of all
84 uninstrumented optimized binaries found the four baselines free of the
injection and the 80 controls retaining their intended predicate, direction,
setup and work in the target timing path. **No timing executable was run.**
This establishes structural readiness of these control recipes, not measured
sensitivity, a candidate table or permission to activate a gate. C0 and T0
remain unset; scheduled evidence capture and qualification are still required.

## Untimed validation

The separate counted probes use the same source recipe with counters added
outside the normal measurement binary. They check real input predicates,
original output equality against the unmodified probe, helper calls, injected
operations and actual SM3 compression entry counts. Their output counts in
the CSV are ordered `helper calls;predicate-one calls;work;SM3 compressions`.
The uninstrumented binaries contain none of those counter symbols.

| Target | Left/right predicate | Selected-class modest / gross work | Opposite class / sham |
|---|---|---|---|
| Scalar-field invert | 0 / 1 | 16 / 1024 dependent squarings | 0 |
| Base-field invert | 0 / 1 | 16 / 1024 dependent squarings | 0 |
| Signing nonce split | 0 / 1 on each of two fixed retries | 16 / 1024 squarings per retry, 32 / 2048 per signing call | 0 |
| HMAC-SM3 | 0 / 1 | 1 / 64 added compression blocks | 0 |

Both injection directions were checked in every feature leg. Signing's
four-draw sampler keeps the first valid nonce, so the probe sees nonce 1
for the left class and n−5 for the right class on each retry; the alternating
values in the RNG recipe do not imply alternating selected nonces. Both
classes produce the same original crypto outputs as their respective
unmodified baselines. HMAC baseline/sham compressions are 5 per call;
selected modest/gross probes report 6/69, and the opposite class reports 5.
These counts alone do not qualify an optimized measurement binary.

## Optimized-code inspection

Every uninstrumented binary was inspected through its preserved disassembly
and ELF64 relocation entries. Indirect calls through the GOT were resolved
to their actual helper or HMAC symbol. The CSV records hexadecimal instruction
addresses for the target's start-clock call, injected helper or HMAC call,
and end-clock call. All 80 injected target calls lie between the two clock
calls in the compiled target function; HMAC then calls the helper before
its original inner hashing. Signing retains the helper before scalar
multiplication in the existing fixed-retry path.

For comparison across builds, helper instruction text was normalized by
removing instruction addresses/bytes and objdump comments, replacing branch
addresses with their symbol-relative labels, and replacing RIP-relative
address displacements. Immediates, registers, loop bodies and branch directions
were retained. This gives 15 distinct helper bodies: five scalar-field bodies
shared by invert/sign, five base-field bodies, and five HMAC bodies. Each
recipe has the same normalized body in all four legs. This normalization is
an inspection aid, not binary identity or proof of arbitrary relocation
contents: the CSV retains full binary/disassembly hashes, call targets were
resolved separately, and all HMAC IV vector loads were checked against the
actual 32 bytes in each ELF file.

The following observations apply to every member of those body groups:

- Scalar-field helpers retrieve the real input, shift its top limb by 63,
  consume the predicate through a stack barrier and copy the input state
  before the conditional work. Left variants execute on predicate zero;
  right variants compare with one. The loops load the current four limbs,
  perform the inlined Montgomery square, store the resulting four limbs
  into the same state slots and decrement a retained counter. Modest and
  gross bodies differ in the counter immediate, `0x10` versus `0x400`.
  The final state remains consumed. This includes signing nonce 1; the
  emitted chain is not constant-folded away.
- Base-field helpers inline input retrieval and retain the same top-bit
  predicate, initial-state barrier and direction test. Their square loops
  retain the four-limb load/arithmetic/store dependency and counters of
  `0x10`/`0x400`, followed by final-state consumption.
- Field shams retain input retrieval, predicate consumption and initial/final
  state handling, with no extra square loop. The absence of a conditional
  zero-work branch is expected; the predicate computation remains present.
- HMAC helpers load the first key byte and shift by seven. For the original
  32-byte keys, they copy the key twice to a 64-byte block and consume that
  whole block through an unconditional barrier before the direction branch.
  The scratch SM3 state is initialized and consumed in sham and leak builds.
  The modest helper performs one 64-byte update; the gross helper retains a
  counter from zero to `0x40` over successive updates of the same scratch
  state. The two static compression call sites are alternate buffered/direct
  update paths, not two compressions per update: the initially empty buffer
  and exact 64-byte input yield one compression and an empty buffer after
  each iteration, agreeing with the separate compression-entry counts.
- HMAC gross-left branches into the work block on zero, while gross-right
  falls into it on one; their block ordering differs. HMAC cleanup includes
  a separate 64-byte zeroization loop, also present in the sham. That loop
  is not counted as injected compression work. Scratch state is consumed
  without finalization, and original HMAC processing follows unchanged.

For a concrete default-leg check, scalar modest-left's counter starts at
`0x379c1`, loop begins at `0x379d0`, resulting limbs are written at
`0x37e07`–`0x37e16`, and decrement/backedge occur at `0x37e20`/`0x37e22`.
Base-field modest-left uses counter `0x37b16`, loop `0x37b30`, and
backedge `0x37ecf`. HMAC gross-right tests direction at `0x37aab`, advances
its outer counter at `0x37ac0`, compares with 64 at `0x37ace`, and retains
compression calls at `0x37b8e`/`0x37bbb`. All addresses refer to the specific
hashed binaries, not portable locations or a promise about future builds.

The sign patch also affects the separate `ct_sign` target because both use
the same signing implementation. HMAC's patched one-shot entry likewise
must not be treated as a clean full-suite baseline. Under the accepted
protocol, those builds are used only with exact target plus negative-control
filtering; the unmodified binary supplies full-suite and filtered baselines.
No such timing/filtering execution has occurred in this preparation.

## Failed preparation retained and remaining limits

The first [build-only run 36434282319](https://github.com/frankxue831/gm-crypto-rs/actions/runs/36434282319),
research commit `f54c4221eea4b9ed1a912c5907b5967e5b9af236`, failed in all four
legs when an untimed field-output parser received `EncodedUint` debug text
instead of a byte-vector literal. Each leg had built only the unmodified
normal harness and the first untimed baseline probe. All four partial
archives and their 160 file hashes were preserved and verified. The fix
converts probe output to a byte vector and adds a regression check; it changes
no control helper or timed code. The four unmodified normal binary hashes
match the corrected run exactly. No timing observation was retried or dropped.

The structural recipe review had 3 findings: retain HMAC sham block setup,
avoid claiming probe qualification before validation, and reserve artifact
upload time from the whole job budget. All 3 were fixed, none declined;
13 recipe/preparation/budget tests pass. The job has a 90-minute limit with
a setup-aware preparation deadline and reserved evidence-upload time.

Structural qualification does not establish a tau effect, hosted-runner
sensitivity, prospective coverage or constant-time behavior. Future builds
must match the frozen source, resolution and recipe and undergo their required
build validation; these identities do not waive checks on a changed binary.
The original smoke and September 17 sentinel causes remain unresolved as
recorded in their investigation reports. Existing gates stay unchanged.
