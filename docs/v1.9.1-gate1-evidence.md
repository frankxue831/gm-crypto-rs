## 4. Procedural note for the charter (non-blocking)

Running §8's phase 2 exactly as written surfaces a tension in the recipe itself.

§8 says of phase 2: *"Keep the formatting and boundary commands unchanged."* But
phase 2 also requires injecting the candidate *"through a temporary path
dependency or Cargo `[patch]` override"* — and a path override necessarily writes
an **absolute local filesystem path** into the export's `Cargo.toml`. That is
precisely the kind of local-environment leakage
`ci/check-open-source-boundary.sh` exists to catch, so the boundary command fails
in phase 2 by construction.

Confirmed by isolation: with the pin bump kept and only the `[patch]` block
removed, `./ci/check-open-source-boundary.sh --worktree .` passes. The failure is
an artifact of the gate mechanics, not a property of the release candidate.

The boundary commands validate the *export*, not the *candidate*, and they already
pass in phase 1 — so the substantive check is not lost. Suggested charter
clarification: scope the two boundary commands to phase 1 explicitly, or require
the phase-2 override to be applied after the boundary scan. Recorded here rather
than acted on, since amending a normative charter is a maintainer decision.
