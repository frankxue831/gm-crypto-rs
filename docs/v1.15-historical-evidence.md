# v1.15 historical dudect evidence

**Descriptive extraction, 2026-09-27.** This preserves the historical evidence
required by [the scope](v1.15-scope.md), Q15.10. It does not derive a candidate
table, establish a noise mechanism, validate detection sensitivity, or start
prospective measurement. Existing gates remain authoritative.

## Inventory and provenance

The [archive manifest](v1.15-archive-manifest.csv) identifies 72 first-attempt
`dudect-nightly.yml` runs from 2026-08-11 through the
2026-09-27T12:00:00Z cutoff: 48 scheduled and 24 manually dispatched, with
66 successful, five failed and one cancelled run. Their 288 jobs have 281
successful, five failed and two cancelled job conclusions. All run attempts
are retained, including successful jobs belonging to failed or cancelled runs.

- [Compact corpus](v1.15-nightly-corpus.csv): one row per job, metadata,
  provenance hashes, extraction flags and five **signed** reported `max tau`
  values for each of the four demoted targets, the twin, the fanout and
  `negative_control`.
- [Per-pass samples](v1.15-nightly-samples.csv): 26,471 finite result rows
  across all observed targets, preserving printed signs and decimal precision,
  rounded `n` in millions, `max t`, `max tau`, pass number and seed. Join by
  `job_id` to the compact corpus.
- [Machine summary](v1.15-nightly-summary.json): inventory counts, actual
  compiler identities and SHA-256 hashes of both CSV files.

Every corpus row links its public Actions job and records hashes of the
original ZIP, combined job log and cached jobs-API response. The manifest
also records the ZIP size and retrieval endpoint. Raw archives and API
responses were preserved separately; they are not committed because they
contain incidental environment details. Hashes establish the identity of
those preserved inputs, not continued availability after GitHub retention.
The compact measurements remain available in this repository after expiry.

## Interpretation and explicit absences

`matrix_features` is the job-name feature leg; `bench_features` is the
actual run marker, including `crypto-bigint-scalar`. Every observed job
declared `DUDECT_SAMPLES=100000`. The five passes are repeated measurements
within one job, not five independent nights. Run date is `created_at` in UTC;
manual dispatches and jobs on the same date are separately identified.

`cpu_env` comes from the environment capture's `lscpu` output. `cpu_gate`
comes only from an actual `RUNNER-CPU:` verdict line; 109 jobs lack that
line. The environment CPU is available in all 288 jobs, but is not
retroactively relabelled as a gate-emitted CPU. `image_version` comes from
Runner Image, not the hosted-agent version. `kernel` retains the kernel
release without the ephemeral hostname. `rustc` and `cargo` come only from
the actual `=== Rust ===` capture, never the setup action's own checks.

| Actual captured compiler | Jobs |
|---|---:|
| Rust 1.97.1 (`8bab26f4f`, 2026-07-14) | 156 |
| Rust 1.98.0 (`88d9e12ae`, 2026-08-18) | 60 |
| Rust 1.98.1 (`48a229cea`, 2026-09-01) | 72 |

**None of these jobs captured Rust 1.95.0.** The unchanged setup-action tag
therefore does not establish a fixed effective compiler. These are distinct
historical compiler strata; do not pool them into a supposedly fixed-1.95.0
calibration. `head_sha` identifies source provenance, not the exact dependency
resolution or binary: this extraction cannot recover a missing lockfile or
prove build equivalence.

An empty tau field means absent, never zero. Duplicate results would be
retained with `|` between values and an explicit issue; no duplicates were
observed. The `issues` column is an extraction inventory, **not an
eligibility or gate verdict**. Its 162 nonempty rows include expected target
absences as well as incomplete measurements:

- Fanout is absent in 144 jobs because their feature legs do not enable its
  SIMD target. These are `missing_target:ct_sm4_cbc_decrypt_fanout` flags.
- The twin is absent in 32 jobs from eight dispatched runs on the pre-twin
  tag. They stay in this archive inventory, and are excluded from twin
  statistics.
- Two full-feature jobs printed `n == +0.000M, max t = +inf, max tau = +inf`
  for `noise_floor_fn_invert` in pass 1: [August 11](https://github.com/frankxue831/gm-crypto-rs/actions/runs/31461679436/job/93686280743)
  and [September 24](https://github.com/frankxue831/gm-crypto-rs/actions/runs/35959209718/job/107503940676).
  Those two nonfinite outputs are flagged as malformed results and omitted
  from the finite sample CSV; the affected probe is marked incomplete. They
  are not silently converted to zero or used as usable timing values.
- One [cancelled job](https://github.com/frankxue831/gm-crypto-rs/actions/runs/32590047515/job/97072336538)
  has 73 finite rows and incomplete target output in its fifth pass; it never
  reached the gate. The other cancelled job has complete gate output. Job
  conclusion and measurement completeness are separate facts.

The parser checks observed targets for exactly one result in each pass.
It does not reconstruct every historical version's entire required-target
set. A missing target flag, a successful job or an empty `issues` field
cannot establish eligibility for a future calibration protocol. Printed
`n_millions` is rounded and belongs to the winning crop; it is not an exact
sample count or the declared 100K budget.

## Cross-check against the original scope

The original scope's 63-run / 252-job twin corpus excludes the eight pre-twin
runs and the whole cancelled run (four jobs), even though three jobs in that
cancelled run reached their gates. Keeping these observations in the archive
inventory does not silently add them to that earlier analysis. Its 176
gate-labelled jobs remain 176 when reconstructed from the preserved corpus.

All **4,675 printed target-level `runs=[...]` gate-input lists** across 287
jobs match the absolute signed bench results rounded to the gate's four
printed decimals. No gate-list mismatch was observed. These are a consistency
check within the source logs, not independent experimental replication.

Using the 252-job selection and median of five absolute reported tau values
reproduces **161 demoted-target episodes above 0.20 in 131 jobs**. The twin's
maximum median in those jobs is **0.01985**; its maximum across all 252 jobs
is **0.03423**. The negative control's minimum is **20.04942**. Earlier scope
numbers use the gate's four-decimal values; this extraction preserves the
bench's five decimals. The result supports the existing negative conclusion
about this twin's tracking behaviour, not a cause for the observed spikes.

## Reproduction

The extractor uses Python's standard library only and does not access the
network. For each manifest row, supply `<run_id>-attempt-<attempt>.zip` and
`<run_id>-attempt-<attempt>-jobs.json` in an archive directory. The latter is
the complete response from
`GET /repos/frankxue831/gm-crypto-rs/actions/runs/{run_id}/attempts/{attempt}/jobs?per_page=100`.
Incomplete pagination or mismatched run/attempt identities abort extraction.

```sh
python3 -m unittest discover -s .github/scripts -p 'test_*.py'
python3 .github/scripts/extract_dudect_history.py \
  --manifest docs/v1.15-archive-manifest.csv \
  --archives "$ARCHIVE_DIRECTORY" --output "$OUTPUT_DIRECTORY"
```

The script validates archive hashes and sizes before output, joins job logs
by exact feature leg rather than ZIP/API order, and rejects ambiguous or
unmatched log identities. It flags partial output and unknown fields instead
of imputing values. Reproduction against the preserved input bytes produces
the CSV hashes in the machine summary; a differently serialized jobs-API
response changes its provenance hash even if the API fields are equivalent.
