# v1.20 scope — PKCS#10 SM2 Certificate Signing Requests (`x509::csr`)

**Status:** **draft / pre-registration (2026-11-28).** Written against `main` on
the `1.19.0` line (`81e36e0`); awaits maintainer sign-off before implementation.
Mirrors [v1.18 scope](v1.18-scope.md) and [v1.19 scope](v1.19-scope.md)
(why-now → structural facts → decisions Q20.1–Q20.6 → wire profile → assurance
→ risks → out of scope → sequence).

One focused, **strictly additive** Rust-core workstream: zero breaking changes,
zero new runtime dependencies, `#![no_std]` + `alloc` in `gmcrypto-core`,
`unsafe_code = "forbid"` in `gmcrypto-core`, MSRV **1.87** / edition **2024**,
zero C ABI additions (`gmcrypto-c` and `gmcrypto-simd` stay unchanged apart from
the eventual lockstep `1.20.0` version bump).

---

## 1. Why now

- **Completing the SM2 enrollment loop.** `gmcrypto-core` already ships SM2 key
  generation (`Sm2PrivateKey::generate`, v1.18), PKCS#8 / PEM key serialization
  (`pkcs8`, `pem`), `SubjectPublicKeyInfo` (`spki`), X.509 certificate parsing
  and chain verification (`x509`), and the TLCP toolkit (`tlcp`). Callers
  provisioning SM2 or TLCP leaf certificates still cannot generate or verify a
  PKCS#10 Certificate Signing Request (RFC 2986 / GM/T 0015) without pulling an
  external ASN.1/PKI stack.
- **Zero new dependencies.** Almost every building block—strict-canonical DER
  reader/writer (`asn1::{reader, writer, oid}`), `spki::{encode, decode}`,
  `sm2::{sign_with_id, verify_with_id}`, `pem::{encode, decode}`, and
  `x509::KeyUsage`—is already in-tree.
- **Core-first discipline.** Following the v1.18 → v1.19 pattern, landing the
  Rust API first lets ergonomics, DER edge cases, and fuzz coverage settle
  before any C ABI projection is locked in.

## 2. Structural facts

- **F1 — `x509` is currently a single file (`crates/gmcrypto-core/src/x509.rs`)
  gated by `feature = "x509"`.** Splitting it into `src/x509/mod.rs` +
  `src/x509/csr.rs` (keeping all existing `gmcrypto_core::x509::*` items
  unchanged at the module root) is 100% SemVer-transparent and adds no new
  Cargo feature flag to CI matrices.
- **F2 — `spki::{encode, decode}` enforces strict 65-byte uncompressed SM2
  points.** Per [v1.19 scope Q19.6](v1.19-scope.md#q196--strictly-additive-compressed-sec1),
  `spki::decode` accepts only `id-ecPublicKey` (`1.2.840.10045.2.1`) +
  `sm2p256v1` (`1.2.156.10197.1.301`) with a validated 65-byte `04 || X || Y`
  BIT STRING. Reusing `spki::{encode, decode}` keeps CSRs aligned with
  `x509::Certificate`.
- **F3 — `asn1::reader` and `asn1::writer` already provide strict-canonical DER
  TLV primitives**, including `TAG_SET` (`0x31`), `write_context_tagged_explicit`
  (`0xA0`), `read_context_tagged_explicit` (`0xA0`), and `oid::SM2_SIGN_WITH_SM3`
  (`1.2.156.10197.1.501`) + `oid::KEY_USAGE` (`2.5.29.15`). Missing helpers are
  tiny and internal: `write_set`, `read_set`, `write_utf8_string` /
  `write_printable_string`, and the X.520 / `extensionRequest` /
  `subjectAltName` OID constants.
- **F4 — `x509::Certificate` already establishes the project's PKI conventions:**
  - `from_der(&[u8]) -> Option<Self>` performs structural + public-key validation
    with a single opaque `None` on failure (failure-mode invariant).
  - `verify_signature` / `verify_signature_with_id` return `bool` and default to
    `DEFAULT_SIGNER_ID` (`b"1234567812345678"`).
  - `subject_raw(&self) -> &[u8]` returns the full DER `Name` SEQUENCE TLV.
  - `sm2-sign-with-sm3` `AlgorithmIdentifier` accepts absent or `NULL`
    parameters on parse.
- **F5 — GmSSL 3.2.0 (`gmssl reqgen`, `gmssl reqparse`, `gmssl reqsign`) is
  available as an independent interop oracle**, supporting `-C`, `-ST`, `-L`,
  `-O`, `-OU`, `-CN`, `-sm2_id`, and `extensionRequest` / X.509 issuance.
- **F6 — Fuzzing obligation.** Per [ECOSYSTEM.md §6](ECOSYSTEM.md#6-per-repository-security-baseline),
  every new parser for untrusted structured input requires a dedicated fuzz
  target (`fuzz_pkcs10_csr`) with committed seeds.

## 3. Decisions (Q20.1–Q20.6)

| Decision | Selected contract |
|---|---|
| Q20.1 · Feature & module | Gate behind existing `x509` feature at `gmcrypto_core::x509::csr`. No new Cargo feature flag. |
| Q20.2 · Operations | Full round-trip: build + sign CSRs (DER & PEM) and parse + verify self-signature. |
| Q20.3 · Subject DN | Minimal structured `SubjectName` builder (`C`, `ST`, `L`, `O`, `OU`, `CN`) plus a raw DER `Name` escape hatch (`from_subject_raw`); parsed `CertificationRequest` exposes `subject_raw(&self) -> &[u8]`. |
| Q20.4 · Attributes & `extensionRequest` | Parser structurally validates `[0] IMPLICIT Attributes`, exposing `attributes_raw(&self) -> &[u8]` and `extension_request_raw(&self) -> Option<&[u8]>` (`1.2.840.113549.1.9.14`). Builder emits empty attributes by default plus optional `extensionRequest` carrying `KeyUsage` and/or `SubjectAltName` (DNS names & IPv4/IPv6 addresses). |
| Q20.5 · C ABI discipline | Rust core only in `v1.20.0` (zero C ABI additions); defer C ABI CSR entry points to `v1.21+`. |
| Q20.6 · Verification & PEM | Separate `CertificationRequest::from_der(der) -> Option<Self>` and `verify_signature(&self) -> bool` / `verify_signature_with_id(&self, id: &[u8]) -> bool`, plus `from_pem(&str) -> Option<Self>` and `to_pem(&self) -> String` using RFC 7468 `"CERTIFICATE REQUEST"`. |

### Q20.1 — Feature gate and module placement

PKCS#10 lives at `gmcrypto_core::x509::csr` behind `#[cfg(feature = "x509")]`.
Keeping it under `x509` avoids expanding the CI Clippy / `cargo deny` /
`wasm32` / `api-stability` feature matrices for a closely related zero-dep PKI
module, mirroring how `tlcp` carried v1.6–v1.8 under one flag. Default builds
(`--no-default-features`) remain byte-identical.

### Q20.2 — Full round-trip (build/sign + parse/verify)

Both directions ship in `v1.20.0`:

- **Builder / signer (`CsrBuilder`):** constructs a canonical DER
  `CertificationRequestInfo`, signs it with `Sm2PrivateKey` and a caller-supplied
  `R: TryCryptoRng` via `sign_with_id` (defaulting to `DEFAULT_SIGNER_ID`, with
  a `sign_with_id` method for custom signer IDs), and returns
  `Result<CertificationRequest, crate::Error>` (single opaque `Error::Failed` on
  any RNG error, over-length signer ID, empty/invalid subject or extension
  input, or signing retry exhaustion).
- **Parser / verifier (`CertificationRequest`):** decodes DER or PEM CSRs,
  validates structure and embedded SPKI, retains the exact signed
  `certificationRequestInfo` wire bytes (`cri_raw()`), and verifies the
  self-signature against `subject_public_key()`.

### Q20.3 — Subject `Name` ergonomics

`SubjectName` provides a small, unambiguous structured builder covering the six
standard X.520 attributes used by GmSSL and RFC 5280:

- `country(c: &str)` (`2.5.4.6`, 2-character ASCII `PrintableString`; invalid
  lengths or non-ASCII characters fail cleanly at build time)
- `state(st: &str)` (`2.5.4.8`, `UTF8String`)
- `locality(l: &str)` (`2.5.4.7`, `UTF8String`)
- `organization(o: &str)` (`2.5.4.10`, `UTF8String`)
- `organizational_unit(ou: &str)` (`2.5.4.11`, `UTF8String`)
- `common_name(cn: &str)` (`2.5.4.3`, `UTF8String`)

Each non-empty attribute emits a single-AVA `RelativeDistinguishedName` (`SET {
SEQUENCE { OID, value } }`) in deterministic order, wrapped in a `SEQUENCE`.
`CsrBuilder::from_subject_raw(subject_der: &[u8])` accepts a caller-encoded DER
`Name` `SEQUENCE` TLV (validated structurally via `asn1::reader::read_sequence`
so callers needing custom OIDs or multi-valued RDNs are never blocked).

Parsed `CertificationRequest` exposes `subject_raw(&self) -> &[u8]`, matching
`x509::Certificate::subject_raw()`. Full RFC 4514 DN string parsing/formatting
remains out of scope.

### Q20.4 — `[0] IMPLICIT Attributes` and `extensionRequest`

RFC 2986 §4.1 defines `attributes [0] IMPLICIT Attributes` (`SET OF Attribute`),
encoded on the wire with tag `0xA0` wrapping zero or more
`Attribute ::= SEQUENCE { type OID, values SET OF ANY }` elements.

- **Parse:** `from_der` strictly validates the `0xA0` container and every
  contained `Attribute` TLV (`SEQUENCE { OID, SET { ... } }`), exposing:
  - `attributes_raw(&self) -> &[u8]` (the raw content bytes inside `[0]`,
    empty slice when `A0 00`).
  - `extension_request_raw(&self) -> Option<&[u8]>` — locates the RFC 2985
    `extensionRequest` attribute (`1.2.840.113549.1.9.14`), validates that its
    `SET` holds exactly one `Extensions` `SEQUENCE` of structurally valid
    `Extension` entries, and returns that raw `Extensions` `SEQUENCE` TLV
    (matching `Certificate::extensions_raw()`). Duplicate `extensionRequest`
    attributes or malformed inner `Extensions` cause `from_der` to return `None`
    rather than silently picking one.
- **Build:** `CsrBuilder` emits empty attributes (`A0 00`) by default. Optional
  typed extension helpers append into a single `extensionRequest` attribute:
  - `key_usage(ku: KeyUsage, critical: bool)` (`2.5.29.15`, reusing `x509::KeyUsage`
    minimal-bit-string encoding per RFC 5280 §4.2.1.3).
  - `san_dns(name: &str)` and `san_ip(ip: IpAddr)` / `[u8; 4]` / `[u8; 16]`
    (`2.5.29.17`, `SubjectAltName` `SEQUENCE OF GeneralName` using `[2] IMPLICIT
    IA5String` for DNS and `[7] IMPLICIT OCTET STRING` for IPv4/IPv6; DNS names
    validated as non-empty ASCII, `core::net::IpAddr` is `#![no_std]` in Rust
    1.77+ / MSRV 1.87).
  - Duplicate extension OIDs are avoided by coalescing all SAN entries into one
    `subjectAltName` extension and storing at most one `keyUsage` extension.

### Q20.5 — Rust-core-first (`gmcrypto-c` unchanged)

No C ABI entry points are added in `v1.20.0`. `crates/gmcrypto-c/include/gmcrypto.h`
remains unchanged. Any future C ABI CSR surface (parse/verify and/or builder)
belongs in a follow-up cycle once the Rust types and error shapes have real
usage.

### Q20.6 — Parse/verify separation and PEM helpers

- `CertificationRequest::from_der(der: &[u8]) -> Option<Self>` validates the
  entire ASN.1 structure and embedded SM2 `SubjectPublicKeyInfo` (on-curve,
  non-identity, uncompressed 65-byte point), stores the exact wire
  `certificationRequestInfo` bytes (`cri_raw()`), the raw DER signature bytes
  (`signature_raw()`), and the complete DER bytes (`to_der()`), and **does not**
  verify the self-signature automatically.
- `csr.verify_signature(&self) -> bool` verifies the self-signature over
  `cri_raw()` using `subject_public_key()` and `DEFAULT_SIGNER_ID`.
- `csr.verify_signature_with_id(&self, id: &[u8]) -> bool` verifies using an
  explicit signer ID (mirroring `x509::Certificate::verify_signature_with_id`
  and `gmssl reqsign -req_sm2_id`).
- `CertificationRequest::from_pem(pem_str: &str) -> Option<Self>` and
  `csr.to_pem(&self) -> String` wrap `pem::{decode, encode}` with RFC 7468
  label `"CERTIFICATE REQUEST"` (legacy `"NEW CERTIFICATE REQUEST"` is not
  emitted; acceptance of only `"CERTIFICATE REQUEST"` keeps PEM handling strict
  and consistent with `pkcs8`/`pem`).

## 4. Wire profile (RFC 2986 / GM/T 0015)

```text
CertificationRequest ::= SEQUENCE {
    certificationRequestInfo  CertificationRequestInfo,
    signatureAlgorithm        AlgorithmIdentifier,      -- sm2-sign-with-sm3 (1.2.156.10197.1.501)
    signature                 BIT STRING                -- unused_bits = 0, DER ECDSA-Sig-Value { r, s }
}

CertificationRequestInfo ::= SEQUENCE {
    version       INTEGER { v1(0) },                    -- strictly 0
    subject       Name,                                 -- DER SEQUENCE (RDNSequence)
    subjectPKInfo SubjectPublicKeyInfo,                 -- id-ecPublicKey + sm2p256v1 (65-byte uncompressed)
    attributes    [0] IMPLICIT Attributes               -- 0xA0 wrapping 0+ Attribute SEQUENCEs
}
```

- **Strict DER rules:** no trailing bytes at any layer, minimal lengths
  (`< 16 MiB`), `version == 0` strictly, `signatureAlgorithm` OID must be
  `1.2.156.10197.1.501` with parameters absent or `NULL` on parse (emitted
  absent on build, matching GM/T 0015 and OpenSSL/GmSSL), `signature` BIT STRING
  must have `unused_bits == 0` and contain a non-empty DER payload (validated as
  canonical `(r, s)` during `verify_signature`).
- **No trust or CA issuance decisions:** `verify_signature()` proves only proof
  of possession of the private key matching `subjectPKInfo` over the exact
  `certificationRequestInfo` wire bytes.

## 6. Risks

- **ASN.1 `SET` DER canonical sorting (X.690 §11.6).** `SET OF` elements in DER
  must be ordered lexicographically by encoded bytes. When `CsrBuilder` emits a
  single-element `RDN` (`SET` of 1 AVA) and a single `extensionRequest`
  attribute (`SET` of 1 `Extensions` `SEQUENCE`), sorting is trivially satisfied;
  if multiple attributes are ever supported later, explicit DER-lexicographic
  sorting must be enforced.
- **`KeyUsage` BIT STRING unused-bits encoding.** RFC 5280 §4.2.1.3 requires
  trailing zero bits in the `KeyUsage` BIT STRING to be omitted (e.g.
  `digitalSignature` = bit 0 → `03 02 07 80`, not `03 03 00 80 00`). Incorrect
  padding breaks strict DER verification and CA interop; unit tests and
  `x509::Certificate::key_usage()` round-trips must pin exact bytes.
- **`SubjectName` string tag rules.** `countryName` (`C`, `2.5.4.6`) MUST be
  encoded as `PrintableString` (2 ASCII letters per RFC 5280 Appendix A.1),
  never `UTF8String`; `CN`/`O`/`OU`/`ST`/`L` use `UTF8String` (supporting
  Chinese/Unicode organization names directly).
- **GmSSL `reqgen` `AlgorithmIdentifier` parameter quirk.** Check during interop
  whether GmSSL 3.2.0 emits `NULL` or absent parameters for `sm2-sign-with-sm3`
  on CSRs; accepting both on parse while emitting absent (or matching GmSSL
  verification behavior) will be verified against `gmssl reqsign` before merge.

## 7. Out of scope

- C ABI (`gmcrypto-c`) CSR bindings (deferred to `v1.21+`).
- Compressed SEC1 C ABI entry points (`gmcrypto_sm2_pubkey_{from,to}_sec1_compressed`, deferred to `v1.21+`).
- RustCrypto `signature-traits` (`signature` crate adapters) and hardware GHASH
  fast reduction in `gmcrypto-simd` (separate future cycles).
- X.509 certificate issuance / CA signing (`CertificateBuilder`).
- Full RFC 4514 DN string parser / formatter or arbitrary `Attribute` decoding
  beyond `extensionRequest`.
- Compressed SPKI keys in CSRs (SPKI remains strictly 65-byte uncompressed).
